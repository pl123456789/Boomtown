# Boomtown v0.10.0 – Foundation Cleanup, Character System, and World Quality Pass

**Date:** July 18, 2026

---

# Summary

This milestone strengthened Boomtown's shared character architecture, stabilized Unity 6 rendering, rebuilt the procedural prospector character, added code-driven walking, and improved the procedural Fraser Canyon world.

The central architectural decision is that Bill, Ted, future employees, and future co-op players should all use the same underlying needs and activity systems. A character may be controlled by a person or by AI, but should not require a separate gameplay implementation.

---

# Objectives Completed

## Unified Character Needs System

Implemented `EmployeeNeeds` and attached it to both Bill and Ted.

Current needs:

- Hunger
- Rest

Despite the current class name, this is intended to become a universal character-needs system rather than an employee-only feature.

This supports the long-term multiplayer plan in which:

- Any player can perform any job.
- Any employee can be directly controlled.
- AI can take over a character when needed.
- Player-controlled and AI-controlled characters follow the same simulation rules.

---

## Shared Waypoint and Activity Architecture

Extracted shared queued-waypoint and work-activity logic into:

`WaypointActivityRunner`

It is now shared by:

- The player controller
- The employee AI mover

The two character types retain different movement backends, but use one activity runner for common behavior.

Current responsibilities include:

- Queued waypoint execution
- Gold-panning activity
- Shared activity state

This removes duplicated gameplay logic and establishes a common foundation for future activities such as:

- Prospecting
- Harvesting
- Hauling
- Construction
- Logging
- Crafting
- Operating businesses

---

## Unity 6 Render Pipeline Fix

Investigated repeated `BatchDrawCommand` errors after procedural world generation.

### Root Cause

Unity 6's GPU Resident Drawer conflicted with runtime-instantiated procedural meshes.

### Resolution

Disabled the GPU Resident Drawer in the active URP asset.

### Result

- Eliminated the flood of rendering errors.
- Restored stable runtime generation.
- Kept the procedural terrain and world systems usable in Unity 6 URP.

---

## Procedural Character Generator Rebuild

Rebuilt the character generator from the earlier blocky mannequin into a cleaner stylized prospector.

Development progression included:

- Capsule-based limbs
- Shoulder pivots
- Elbow pivots
- Hip pivots
- Knee pivots
- Improved body proportions
- Better grounding
- Cleaner frontier silhouette

The limbs are no longer simple rigid rods. The new pivot hierarchy allows the procedural animation system to bend arms and legs at real joints.

The separately developed design-tool additions were reviewed and merged as Character Generator version 3.6.

Character options now include:

- Suspenders
- Optional bandana
- Optional satchel
- Pickaxe
- Gold pan

This character is intentionally generated without requiring an imported skeletal rig.

---

## Procedural Walk Animation

Implemented a code-driven walking animation with no imported animation clips or skeleton requirement.

Features:

- Sine-driven gait cycle
- Contralateral movement
- Opposite arm and leg swing
- Knee folding during leg swing
- Elbow folding during arm swing
- Compatibility with the generated joint hierarchy

The walk was reviewed against recorded gameplay video.

A reversed knee-bend direction was identified during review and corrected.

### Result

Boomtown now has a reusable procedural locomotion foundation for generated characters.

---

## Fraser Canyon Terrain and World Quality Pass

Reviewed the Hope and Yale world generators against the intended 1858 Fraser Canyon setting.

### River and Canyon

- Widened the river valley's lateral meander range.
- Reduced the tendency for the canyon to remain centered in every seed.
- Improved variation between generated worlds.

### Rolling Terrain

Added a broader rolling-hills layer so terrain beyond the immediate canyon is no longer unnaturally flat.

### Rock-Shelf Bug Fix

Fixed a case where the rock-shelf pass could gouge a crater into the canyon wall on sharp river bends.

### Terrain Material Fix

Corrected the grass, dirt, and rock terrain layers reading excessive smoothness from texture alpha channels.

This removed the unnaturally shiny appearance from the terrain.

# Architectural Impact

This milestone establishes several long-term Boomtown principles:

- Player and employee systems should be unified wherever possible.
- Control source and gameplay capability should remain separate concerns.
- Shared activities should not be duplicated between player and AI controllers.
- Procedural characters can support gameplay before a full skeletal-animation pipeline is introduced.
- Runtime world generation must remain compatible with the selected Unity render configuration.
- The procedural terrain should resemble the geography and visual character of the 1858 Fraser Canyon rather than a generic centered river valley.
